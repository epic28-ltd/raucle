# X1: Schema-bound tool-call enforcement

**Status:** core enforcement + MCP source shipped in this slice; OpenAPI
fragment source shipped alongside (minimal, fail-closed). **Backlog:**
X1 (1964). **Owner:** epicS build wave.

## Problem

The capability gate enforced policy rules on the argument *names* the
policy declared. It did not consult the tool's parameter schema, so:

* a rule referencing a field the tool does not declare silently
  over-enforced (the rule could never bind to a real call), and
* a type-confused argument — the string `"99999"` supplied for a
  `number` field with no `max_value` bound in the rule — was not
  structurally denied: with no bound, `max_value` had nothing to check
  and the value passed as "unconstrained".

## Design (X1)

`raucle/tool_schema.py` binds the gate to the tool's declared schema.

### Load-time (config load refuses)

* `ToolSchemaRegistry.register(name, schema)` validates the fragment
  shape (object-typed, dict `properties`).
* `ToolSchemaRegistry.bind_policy(tool, constraints)` is the config-load
  entry point. It raises **`SchemaPolicyLoadError`** naming the tool and
  the field when the rule references a field the schema does not declare
  (all rule kinds: `forbidden_values`, `allowed_values`, `starts_with`,
  `max_value`, `min_value`, `required_present`,
  `forbidden_field_combinations`), when the tool has no registered
  schema at all, or when the same tool is registered twice with
  conflicting schemas.
* Schema/rule conflicts therefore fail at load, never silently at call
  time.

### Enforcement (call time denies)

`CapabilityGate(tool_schemas=...)` accepts a
`ToolSchemaRegistry`; in gate stage 7a (before the name-based constraint
checks) the call's argument values are validated against the tool's
schema:

* type-confused values deny with a reason prefixed
  **`schema_violation`** — the acceptance case: `amount` declared
  `number`, rule carries **no** bound, args `{"amount": "99999"}` →
  DENY.
* `bool` is never a `number`/`integer` (Python's `bool ⊂ int`
  coercion edge); NaN/±inf are never numbers.
* an undeclared argument denies when the schema sets
  `additionalProperties: false` (closes the "forbidden value smuggled
  under a different parameter name" evasion the docstring previously
  only warned about, for schemas that declare closed objects).
* a tool **without** a registered schema keeps today's behaviour
  exactly (fail-closed over the declared rule set instead of failing
  open).

### Sources

* **Primary — MCP:** `register_from_mcp_tools(tools)` consumes an MCP
  `tools/list` payload (`[{name, inputSchema}, ...]`); a malformed entry
  is a load-time error.
* **Secondary — OpenAPI fragment:** `register_from_openapi_fragment()`
  consumes `{"paths": {...}}` operations with an `operationId` and a
  JSON `requestBody` schema or query `parameters`; schema-less
  operations fail at load.

## Policy-file contract

The paper eval policy set (`paper/eval/policies/*.json`) stays at its
pre-registration hashes: **any change to those files requires updating
`paper/eval/PRE-REGISTRATION.md` in the same commit** (CI hashes both;
see the "Verify policy hashes" job in `.github/workflows/ci.yml`). This
slice changes none of them — the schema binding is registry-based and
orthogonal to the frozen eval policies.
