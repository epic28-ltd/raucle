- feat(verifier): auditor-facing offline provenance verifier CLI (issue #346, ADR 0011 items 1-3): a new `raucle-verify` console script in `pyproject.toml` running `raucle.verifier_cli`, a thin front end with no crypto of its own over the canonical `ProvenanceVerifier` (trust roots loaded and `--require-pq` enforced through the existing canonical loaders, so a second implementation cannot drift).
- feat(verifier): stable versioned machine output (schema `raucle.verify.report/v1`): additive `--json` flag on `raucle provenance verify` and the auditor CLI emitting a deterministic report object (verdict, named failure reasons passed through verbatim with line numbers and classes, checked-artifact digests, honest coverage rows naming performed and skipped checks) plus a stable exit-code table documented in `docs/spec/verifier-coverage-inventory.md`: 0 verified, 1 operational error, 2 invalid, 3 unsupported profile, 4 missing trust material, 5 policy requirement unmet, 6 PQ runtime unavailable. Without `--json` the default human output and legacy exit codes are unchanged byte-for-byte.
- feat(verifier): fail-closed classification: unrecognised failure reasons report verbatim under an `unclassified` label and never yield a verified verdict; empty bundles are invalid under the versioned contract; missing trust roots (referenced `kid`/`pqk` with no supplied root) are named by a read-only header scan because the canonical error stream reports a missing key exactly like a bad signature.
