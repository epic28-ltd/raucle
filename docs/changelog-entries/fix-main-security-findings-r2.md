- Security findings cleared on main (SonarCloud analysis of 26 Nov 2026): the receipt sidecar HTTP responder no longer reflects request-supplied bytes into response bodies (pythonsecurity:S5131, BLOCKER, reflected XSS via HTTP request body). Every sidecar response is JSON built from fixed named status strings, computed counters and store-held values only; the two 503 refusals (`nonce_store_unavailable`, `receipt_sink_overflow`) drop the `refused_receipt` echo of the request envelope, and the refused hash remains receipted by the gateway's own signed `x_sidecar` advisory. Hostile-request-body marker tests pin the property by grep over every reachable raw response (202, 200 duplicate, 400 invalid envelope, 409 nonce reuse, 400 invalid nonce, 503) in `tests/test_sidecar_submit_antireplay.py`, and the x3 sidecar spec's overflow contract now says so.
- Path-traversal hardening on the provenance verifier (pythonsecurity:S8707, MAJOR, reachable from `raucle provenance verify`): `ProvenanceVerifier.verify_chain` canonicalises the caller-supplied chain path once at its first use (`Path.expanduser().resolve()`), refuses any path that names no existing regular file with the verifier's named `FileNotFoundError`, and reads only the canonicalised path afterwards; no containment comparison is introduced because the flow is read-only. This applies the same engine-proven CLI-input recipe already shipped in the policy regression and verifier CLI paths. Refusal and existing-verify behaviour are pinned at the canonicalise point in `tests/test_provenance.py`.
