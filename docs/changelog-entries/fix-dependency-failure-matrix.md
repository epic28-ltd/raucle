- Added the dependency failure matrix (`docs/spec/dependency-failure-matrix.md`, depends issues #344 items 1 and 5, referencing ADR 0010): each enforcement dependency class (policy and config load, trust registry, signer and KMS, replay store, solver and formal proof, telemetry exporter, receipt store, receipt sidecar, downstream boundary) is mapped to its current failure behaviour and the exact passing test id that proves it, with every unproven case marked an explicit GAP (segmented-store crash rollback, receipt-sidecar fsync durability, KMS and handshake signer faults, execution-attestation linkage).
- Added credential, trust-root and revocation freshness fail-closed regressions (`tests/test_identity_freshness_fail_closed.py`, 12 tests): rotated and revoked api keys deny pre-gate, foreign-issuer tokens refuse by name, expired capability tokens refuse, revocation-registry-named token ids refuse, a corrupt or vanished revocation registry refuses token calls by name, and a receipt-signer (KMS) outage after a policy match downgrades the allow to the named `receipt emission failed` deny with receipted recovery after the signer returns.
- Fixed the revocation registry vanishing silently re-opening revoked token ids: `_load_revoked_ids` now remembers every revocations file this process has read and raises a named error when a previously read registry file disappears, which refuses token evaluation by name until the file is restored; a configured-but-never-created registry stays the legitimate pre-first-revocation steady state.
- Fixed an identity-dependency failure escaping `authenticate_caller` as an unaudited exception into the HTTP layer: a corrupt revocation registry on a live token call now returns a named unauthenticated pre-gate refusal (`gate identity dependency unavailable (fail closed)`) instead of a 500.
- Honest limitations recorded: revoked-token denial remains an unattributable pre-gate refusal (reclassifying it would change the receipts contract and is deliberately not done); the vanished-registry refusal state is per-process memory, so a restart before restoration re-enters the absent-before-first-read state; segmented-store crash rollback and sidecar fsync durability remain separate coverage; no live watch mode is claimed.
