raucle offline verifier (X2 slice 1)

Verifies raucle audit packs (PACK.json, manifest, receipt chain) or a bare receipt chain / single receipt entirely in your browser. This page makes no network connections after load — drop in files, get a verdict. Public keys must ship inside the pack (that is what an audit pack is for); nothing is retrieved.

1 · Provide the artefact

drop the pack files here (select the whole pack directory, or the individual files)

— or paste a receipt / chain —

One receipt JWS per line, or {"receipt_hash": …, "jws": …} JSONL envelopes. Verify against the keys the pack carried (below) or a pasted PEM.

3 · The verification recipe this page runs

Verification recipe — what this page checks, in order:

1. PACK.json (index): a JSON object of kind 'raucle-audit-pack/v1'. Verify its
   Ed25519 signature: re-serialise the index WITHOUT audit_public_key_pem and
   index_signature in canonical JSON form (RFC 8785 / JCS: object keys sorted
   by UTF-16 code unit, no insignificant whitespace, UTF-8, integers only),
   and verify the base64 signature with the embedded audit public key.

2. Integrity: every member file listed in the index must be present inside the
   pack (no path escaping the pack root, no unindexed extra files), and its
   sha256 must equal the index's recorded sha256. Anything tampered, missing,
   added, or re-indexed fails here.

3. manifest.json: verify its Ed25519 signature over the canonical form of its
   'body' with the embedded signer public key; then check that signer_key_id
   equals the first 16 hex chars of sha256 over the PEM bytes, and that the
   manifest signer equals the PACK.json audit signer (one custodian).

4. chain.jsonl: one JSON envelope per line, each exactly
   {"receipt_hash": "sha256:", "jws": ""} (duplicate JSON
   keys rejected, unknown envelope fields rejected). For every receipt:
     a. JWS is a 3-segment compact serialization (header.payload.signature);
     b. header and payload decode to canonical JSON (JCS byte-equality);
     c. header: alg 'EdDSA', typ 'provenance-receipt/v1', profile marker
        'raucle/v1' == 'provenance', crit exactly ['raucle/v1'], no other
        header keys; header kid == payload agent_key_id;
     d. payload: typ 'provenance-receipt/v1', non-empty iss;
     e. the Ed25519 signature over the raw signing input
        (base64url(header) + '.' + base64url(payload)) verifies against the
        bundled public key for agent_key_id — fail-closed: an unknown key id
        is a denial, never a pass-through;
     f. receipt_hash equals sha256 over the exact JWS ascii bytes;
     g. every parent receipt_hash cited by the receipt appears in the chain.
   Receipts declaring the PQ ('raucle/pq1') profile are DENIED here: the
   ML-DSA-65 leg cannot be verified in-browser, and a partially verified
   receipt must never be reported as verified. Packs that declare
   require_pq are likewise denied outright.

Trust note: a self-signed pack proves internal consistency only — anyone can
rebuild and sign their own pack. Pin the custodian's audit key id (the
signer shown on a verified pack) out of band to get 'this pack came from
that custodian'.

All of the above is recomputed locally from the dropped bytes alone. The page
performs no network I/O — no keys or data leave the browser, and nothing is
looked up anywhere.
